# Анализатор зависимостей пакетов Ubuntu

Практика № 2, вариант 5. Программа строит граф прямых и транзитивных
зависимостей с помощью обхода в глубину. Стек заменяет рекурсию,
а словарь уже посещённых пакетов останавливает обход по циклам.

Нужен Python 3.10 или новее. Сборка и установка библиотек не требуются.

```bash
sh run.sh examples/config.xml
python3 -m unittest discover -s tests -v
```

В Windows PowerShell:

```powershell
.\run.bat examples\config.xml
py -m unittest discover -s tests -v
```

Корень XML — `config`. Каждое поле задаётся один раз.

| Поле | Значение |
| --- | --- |
| `package` | Имя пакета Ubuntu или заглавная латинская буква в тестовом режиме. |
| `repository` | URL индекса `Packages` или путь к тестовому файлу относительно XML. |
| `test_mode` | `true` для тестового репозитория, иначе `false`. |
| `version` | Точная версия пакета, например `2.10-3build1`. |
| `output` | Имя файла PNG, например `graph.png`. |
| `ascii` | `true` для вывода ASCII-дерева, иначе `false`. |

Укажите прямую ссылку на индекс нужного выпуска, компонента и архитектуры.
В примере это Ubuntu 24.04 (noble), компонент main, архитектура amd64.
Программа сама разбирает поля `Package`, `Version`, `Pre-Depends` и
`Depends`. Для корня выбирается точная версия, для остальных пакетов —
первая запись в указанном индексе. Все альтернативы включаются в граф.
Пакеты без записи в индексе выводятся как листья. Это граф связей по
метаданным одного индекса. Он не моделирует выбор пакетов при установке.

Пример успешного вывода:

```text
hello: libc6
```

Для демонстрации ошибок скопируйте XML и меняйте по одному значению:
`package` → `?`, `repository` → `local`, `test_mode` → `maybe`,
`version` → `unknown`, `output` → `graph.txt`, `ascii` → `maybe`.
Запустите программу с изменённым XML. Ошибка укажет поле, код выхода — 1.
В тестовом режиме файл описывает связи строками вида `A: B C`.
Пакеты обозначаются заглавными латинскими буквами. Лист можно записать
как `B:` или оставить только в списке зависимостей.

```bash
sh run.sh examples/chain.xml
sh run.sh examples/diamond.xml
sh run.sh examples/cycle.xml
```

Первый пример показывает транзитивную цепочку, второй — общую зависимость
двух ветвей, третий — цикл. В выводе каждая вершина появляется один раз.
Интернет для автотестов не требуется.

На этапе 4 флаг `--reverse` выводит пакеты, которые прямо или транзитивно
зависят от выбранного. Программа разворачивает рёбра всего индекса и
использует тот же DFS со стеком. Сам выбранный пакет исключается из вывода,
в том числе при цикле.

```bash
sh run.sh examples/reverse.xml --reverse
sh run.sh examples/cycle.xml --reverse
sh run.sh examples/chain.xml --reverse
```

Ожидаемый вывод по порядку: `B, A, C`, `C, B`,
`Обратных зависимостей нет.`
