# Анализатор зависимостей пакетов Ubuntu

Практика № 2, вариант 5. Этап 2 скачивает индекс пакетов Ubuntu и
показывает прямые зависимости указанной версии пакета.

Нужен Python 3.10 или новее. Сборка и установка библиотек не требуются.

```bash
sh run.sh examples/config.xml
python3 -m unittest discover -s tests -v
```

В Windows PowerShell:

```powershell
.\run.bat examples\config.xml
py -m unittest discover -s tests -v
```

Корень XML — `config`. Каждое поле задаётся один раз.

| Поле | Значение |
| --- | --- |
| `package` | Имя пакета Ubuntu или заглавная латинская буква в тестовом режиме. |
| `repository` | URL индекса `Packages`, `Packages.gz` или `Packages.xz`. |
| `test_mode` | `true` для тестового репозитория, иначе `false`. |
| `version` | Точная версия пакета, например `2.10-3build1`. |
| `output` | Имя файла PNG, например `graph.png`. |
| `ascii` | `true` для вывода ASCII-дерева, иначе `false`. |

Укажите прямую ссылку на индекс нужного выпуска, компонента и архитектуры.
В примере это Ubuntu 24.04 (noble), компонент main, архитектура amd64.
Программа сама разбирает поля `Package`, `Version`, `Pre-Depends` и
`Depends`. Ограничения версий и альтернативы через `|` сохраняются.
Тестовый режим с локальным файлом появится на этапе 3, визуализация — на этапе 5.

Пример успешного вывода:

```text
libc6 (>= 2.38)
```

Для демонстрации ошибок скопируйте XML и меняйте по одному значению:
`package` → `?`, `repository` → `local`, `test_mode` → `maybe`,
`version` → `unknown`, `output` → `graph.txt`, `ascii` → `maybe`.
Запустите программу с изменённым XML. Ошибка укажет поле, код выхода — 1.
Тесты проверяют ошибки всех шести настроек и загрузку индекса через локальный
HTTP-сервер. Интернет для тестов не требуется.
